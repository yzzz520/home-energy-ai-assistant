# AI 助手设计与数据契约

## 1. 产品定位

家庭能源助手负责理解用户问题，调用预测、调度、电价和数据分析工具，并把结构化结果解释给用户。

助手不是预测模型、优化器或电池控制器。它不能自行计算或编造：

- 负荷和光伏预测值
- SOC
- 电价
- 购售电成本
- 节省金额
- 调度原因

这些数据必须由工具返回。

## 2. 用户范围

### `existing_300`

正式支持范围。

允许：

- 查询历史负荷、光伏和净负荷
- 查询预测值和预测误差
- 查询电价和调度计划
- 查询成本、SOC 和规则回退原因
- 运行受控 what-if

### `cold_start`

新用户上传数据并通过校验后的实验模式。

最低要求：

- 30 分钟本地时间戳
- 家庭负荷历史
- 至少 14 天连续数据
- 光伏容量
- 邮编
- 电价方案

可选：

- 光伏发电历史
- 电池参数
- 电价合同

冷启动输出必须标记：

```text
user_scope = cold_start
experimental = true
not_benchmarked = true
```

### `unsupported`

以下情况必须拒绝生成预测或调度：

- 用户不在 300 户范围且未上传数据
- 非 Ausgrid Sydney 覆盖区域
- 数据粒度不是 30 分钟
- 上传数据少于最低要求
- 缺电池参数却要求充放电计划
- 缺电价方案却要求费用结论
- 要求直接控制真实设备
- 要求保证节省金额

## 3. 处理顺序

```text
用户输入
→ 范围识别
→ 意图分类
→ 槽位抽取
→ 必要槽位校验
→ 工具计划
→ 工具执行
→ 数值一致性检查
→ 回答模板
→ 记录评测日志
```

范围判断优先于意图判断。不得把未知用户静默映射成已有 300 户中的任意一户。

## 4. 模型兼容边界

当前全局预测模型包含类别特征：

```text
Customer
Postcode
cluster_id
```

冷启动用户：

- `Customer` 必须映射为 `unknown_new_user`
- 未见过的邮编必须映射为 `unknown_postcode`
- 有足够历史负荷后再预测聚类
- 不得伪造已有客户编号

第一版可以只实现 `known_user_forecast`；冷启动预测接口在契约中保留，功能后续实现。

## 5. 工具原则

- 所有工具使用版本化 JSON 契约。
- 所有响应包含 `status`、`user_scope`、`data`、`evidence`、`warnings`。
- `evidence` 至少包含数据来源、模型版本和生成时间。
- 工具只能访问当前会话授权的用户数据。
- LLM 不允许拼接任意 SQL、文件路径或 Python 代码。
- 工具失败时必须显式返回错误码，不能返回猜测值。

## 6. RAG 边界

RAG 只允许存放静态知识：

- 电价规则说明
- 电池安全规则
- 设备说明
- 节能知识
- 系统操作说明

实时预测、SOC、成本和调度结果必须通过工具获取，不能写入知识库。

## 7. 回答规则

- 明确区分事实、预测、优化结果和建议。
- 回答中的预测值、成本和 SOC 必须与工具结果一致。
- 预测驱动调度没有优于规则时必须如实说明。
- 规则回退必须说明回退原因。
- 冷启动结论必须标注实验性质。
- 无法确定时先澄清，不猜测客户、日期或目标。

## 8. 评测集设计

每条评测样本包含：

- 用户原话
- 真实意图
- 用户范围
- 期望槽位
- 应调用工具
- 禁止调用工具
- 期望结果类型
- 回答必须包含的要点

建议第一版规模：

```text
已有 300 户查询：120 条
新用户与范围问题：40 条
超范围与安全拒绝：30 条
缺槽位澄清：30 条
工具错误场景：20 条
总计：240 条
```

至少按意图、用户范围、日期表达方式和缺槽位情况分层。

## 9. 评测指标

- 意图准确率
- 宏平均 F1
- 槽位准确率
- 工具召回率
- 工具精度
- 禁止工具调用率
- 工具调用成功率
- 数值一致率
- 回答正确率
- 澄清准确率
- 安全拒绝准确率
- 幻觉率
- P95 响应时延

数值一致率必须逐项回查工具结果，不允许由 LLM 自评。
